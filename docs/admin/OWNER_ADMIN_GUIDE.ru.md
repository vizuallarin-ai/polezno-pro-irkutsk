# Руководство владельца — админка ИркПортала

Короткая операционная памятка после ADMIN.B–F. Не заменяет технический runbook.
Не используйте устаревший `docs/admin-guide.md` — он расходится с текущим UI.

## Вход

1. Откройте `/admin`.
2. Войдите email + пароль.
3. Роли: **Владелец** (основной доступ), **Контент-редактор** (только контент), **Разработчик** (техника).

Сброс пароля: попросите разработчика выполнить безопасный reset-скрипт на сервере (не публикуйте пароли в чатах).

## Главная

На `/admin` заголовок **Главная** (в браузере вкладка может писать «Dashboard» — это оболочка Payload).

Блоки на странице:

- **Требует внимания** — что сделать сегодня (заявки, готовность, черновики).
- **Готовность к запуску** — критерии контента.
- **Заявки** — только у владельца/разработчика (редактор этого блока не видит).
- **Контент** / **Черновики** / **Быстрые действия** / **Открыть сайт**.

Отдельного пункта меню «Внимание» нет — всё на Главной.

## Заявки (только Владелец / Разработчик)

1. Раздел **Заявки** (или карточки с Главной).
2. Новые → возьмите в работу (**Нужно связаться**) → поле **Следующая связь**.
3. Дальше по статусам: **Обсуждение** → **Забронировано** → **Завершено**.
4. Отказ: статус **Отказ** + причина. Спам: **Спам**.
5. **Не удаляйте** заявки — удаление отключено для владельца.

## Экскурсия

1. **Экскурсии** → Создать.
2. Заполните название; slug создаётся сам (можно поправить).
3. Сохраните черновик.
4. Перед публикацией смотрите блок **«Перед публикацией экскурсии»**. Нужны: **краткое описание**, цена (или «по запросу»), длительность.
5. Статус → **Опубликован**. Если чего-то не хватает — админка не даст опубликовать (текст ошибки смотрите в форме).

## Маршрут

1. **Маршруты** → Создать.
2. Нужны: название, **краткое описание**, ≥1 точка с координатами (см. блок **«Перед публикацией маршрута»**). Для платного маршрута — цена.
3. Черновик → проверка → **Опубликован**.

## Статьи

1. **Статьи**.
2. Управляйте полем **Статус публикации** (черновик / опубликован / скрыт / архив).
3. Технические кнопки Payload draft / `_status` можно игнорировать — канон для сайта: **Статус публикации** (синхронизируется автоматически).

## Фото и отзывы

Публикуйте через статус. Некачественные материалы сначала **Скрыт** или **В архиве**, не удаляйте сразу.

## Восстановление версии

Если ошибочно сохранили экскурсию/маршрут/статью/отзыв/фото/гид:

1. Откройте документ.
2. В правой/боковой панели Payload: **Versions** → выберите прошлую → **Restore** (подписи на английском — это стандарт Payload, не ошибка установки).
3. Проверьте сайт/превью.

У заявок истории версий нет.

## Вместо удаления

| Ситуация | Действие |
|---|---|
| Убрать с сайта | Скрыт / снять с публикации |
| Больше не нужно | В архиве |
| Заявка закрыта | Завершено / Отказ / Спам |
| Файл медиа | Попросите разработчика |

## Роли — что нельзя

- Редактор: нет заявок, нет пользователей, нет system Places/Partners.
- Владелец: не назначает роль «Разработчик», не удаляет разработчика.
- Никто не удаляет последнего владельца/разработчика (защита от lockout).

## Чеклист приёмки владельца

Используйте перед коммерческим запуском (на тестовой/локальной копии, не ломая production):

- [ ] Я могу войти
- [ ] Я понимаю Главную (внимание / готовность / заявки)
- [ ] Я вижу новые заявки
- [ ] Я могу создать экскурсию / маршрут / статью / фото / отзыв
- [ ] Я понимаю блокировку публикации
- [ ] Я могу обработать заявку и поле «Следующая связь»
- [ ] Я могу восстановить версию (Versions → Restore)
- [ ] Я понимаю, что нельзя удалять
- [ ] Основные действия возможны с телефона
- [ ] Знаю, куда писать при аварии

Полный список: `docs/admin/ADMIN_F_OWNER_ACCEPTANCE.md`.

## Если что-то сломалось

1. Не паникуйте и не удаляйте данные.
2. Проверьте, не черновик ли материал.
3. Попробуйте восстановить версию.
4. Напишите разработчику: что меняли, когда, URL страницы.
5. Авария БД/сервера → разработчик по `docs/ops/ADMIN_RECOVERY_RUNBOOK.md`.
